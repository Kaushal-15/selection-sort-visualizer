Algorithm Basics

How Selection Sort Works

Selection Sort divides the array into two logical sections: a sorted sublist built from left to right, and an unsorted sublist occupying the rest of the array.

01

Scan Unsorted Prices

In pass i (from 0 to n - 2), start by assuming the element at index i is the minimum. Then scan elements from index j = i + 1 to n - 1 to search for any smaller price.

02

Identify the Minimum

Whenever an item with a price lower than the current minimum candidate is discovered, update the minimum index record minIndex = j. Continue scanning until the end of the array.

03

Swap to Sorted Boundary

After scanning, if minIndex ≠ i, swap array[i] with array[minIndex]. If the minimum is already at index i, skip the swap. Index i is now permanently sorted!

04

Repeat for n - 1 Passes

Advance the sorted partition boundary by one. Repeat the process for n - 1 passes. When only one element remains at the end, it is guaranteed to be in its correct place.

Implementation

C Program: Selection Sort for Product Prices

A production-ready C program that reads the number of products $n$ and their prices, sorts them in ascending order using Selection Sort, prints the array state after each pass, and outputs the final sorted catalog.

selection_sort_prices.c 
/*
 * Product Price Sorter: Selection Sort in C
 * Sorts an array of product prices in ascending order.
 * Prints the array after every pass.
 */

#include <stdio.h>

// Function to print current product price array
void printArray(int prices[], int n) {
    printf("[ ");
    for (int i = 0; i < n; i++) {
        printf("INR %d", prices[i]);
        if (i < n - 1) printf(", ");
    }
    printf(" ]\n");
}

// Selection Sort algorithm implementation
void selectionSort(int prices[], int n) {
    int comparisons = 0;
    int swaps = 0;

    printf("\n--- Starting Selection Sort ---\n");
    printf("Initial Prices: ");
    printArray(prices, n);

    // Run n - 1 passes
    for (int i = 0; i < n - 1; i++) {
        int minIndex = i;

        // Find the index of the minimum price in the unsorted range [i .. n-1]
        for (int j = i + 1; j < n; j++) {
            comparisons++;
            if (prices[j] < prices[minIndex]) {
                minIndex = j;
            }
        }

        // Swap minimum element with element at index i if needed
        if (minIndex != i) {
            int temp = prices[i];
            prices[i] = prices[minIndex];
            prices[minIndex] = temp;
            swaps++;
            printf("Pass %d: Swapped index %d (INR %d) <-> index %d (INR %d)\n",
                   i + 1, i, prices[minIndex], minIndex, prices[i]);
        } else {
            printf("Pass %d: Minimum already at index %d (INR %d). No swap needed.\n",
                   i + 1, i, prices[i]);
        }

        printf("         Array after Pass %d: ", i + 1);
        printArray(prices, n);
    }

    printf("\n--- Sorting Finished ---\n");
    printf("Total Comparisons: %d\n", comparisons);
    printf("Total Swaps:       %d\n", swaps);
}

int main(void) {
    int n;

    printf("Enter number of products: ");
    if (scanf("%d", &n) != 1 || n <= 0) {
        printf("Invalid number of products.\n");
        return 1;
    }

    int prices[n];
    printf("Enter %d product prices:\n", n);
    for (int i = 0; i < n; i++) {
        if (scanf("%d", &prices[i]) != 1) {
            printf("Invalid price entry.\n");
            return 1;
        }
    }

    selectionSort(prices, n);

    printf("\nFinal Sorted Product Prices (Ascending):\n");
    for (int i = 0; i < n; i++) {
        printf("%d. INR %d%s\n", i + 1, prices[i], (i == 0) ? " (Cheapest)" : "");
    }

    return 0;
}

Theoretical & Real-World Evaluation

Complexity Analysis

An in-depth breakdown of Selection Sort's asymptotic time complexity, space requirements, comparison counts, swap bounds, and stability characteristics.

Metric Complexity / Bound Why / Mathematical Derivation
Best-Case Time O(n²) Even if the array is already sorted, the algorithm still compares every pair in the unsorted range to find the minimum.
Average-Case Time O(n²) On average, random price distributions require checking all remaining elements in each pass.
Worst-Case Time O(n²) Occurs when array is reverse sorted; still performs exactly $\sum_{i=1}^{n-1} i = \frac{n(n-1)}{2}$ comparisons.
Auxiliary Space O(1) In-place algorithm. Only requires a few primitive pointer variables (i, j, minIndex, temp).
Total Comparisons n(n - 1) / 2 Fixed for any input of size $n$: $(n-1) + (n-2) + \dots + 1 = \frac{n(n-1)}{2}$. Independent of input order.
Total Swaps At most n - 1 At most 1 swap per pass. Best case is 0 swaps (when array is already sorted). Much fewer writes than Bubble Sort ($O(n^2)$ swaps).
Stability Not Stable Long-range swaps can reverse the relative order of duplicate elements. (See detailed stability proof below).
Algorithm Type In-place, Comparison Sort Modifies the original array directly without allocating secondary storage.

Why is Selection Sort Not Stable?

A sorting algorithm is stable if it preserves the relative original order of items with identical keys (equal values).

Selection sort makes long-range swaps across several elements. Consider two identical product prices: Product A (₹499) at index 0 and Product B (₹499) at index 1, followed by Product C (₹199) at index 2:

Initial Array:
₹499 [A] ₹499 [B] ₹199 [C]
Pass 1: Min is ₹199 at index 2. Swap index 0 with index 2.
Result Array:
₹199 [C] ₹499 [B] ₹499 [A]

Notice that Product B (₹499) now appears before Product A (₹499)! Their original relative order was inverted, proving that Selection Sort is unstable.

💡

When Should You Use Selection Sort?

While $O(n^2)$ time makes Selection Sort inefficient for large datasets compared to Quick Sort or Merge Sort ($O(n \log n)$), it offers distinct physical advantages:

  • Minimal Memory Writes ($O(n)$ swaps): Selection Sort makes at most $n - 1$ swaps. When memory write cycles are physically costly (such as in Flash memory, EEPROM, or solid-state devices with limited write endurance), Selection Sort outperforms algorithms like Insertion Sort or Bubble Sort which execute up to $O(n^2)$ write cycles.
  • Strict $O(1)$ Memory Overhead: Performs strictly in-place with zero additional heap allocation, making it suitable for severely constrained microcontrollers and embedded firmware.
  • Small Datasets & Simplicity: For very small arrays (e.g. $n \le 15$), the overhead of recursive calls in Merge Sort / Quick Sort makes simple iterative sorts competitive and easier to audit.
  • Pedagogical Value: Ideal for introducing partition-based sorting, loop invariants, and algorithm efficiency metrics.
